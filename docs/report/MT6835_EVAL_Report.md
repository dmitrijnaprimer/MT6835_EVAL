## 1. Введение

MagnTek MT6835 — 21-битный AMR-энкодер с тремя уровнями калибровки: заводская, User Auto-Cal и NLC (Non-Linearity Compensation). Документация MagnTek заявляет достижимую точность ±0.02° после успешной калибровки NLC, однако не раскрывает ни формат NLC-таблицы, ни шаг дискретности корректирующих значений.

Задача работы: разработать испытательный стенд и управляющее ПО для оценки линейности энкодера MT6835, экспериментально определить параметры NLC, реализовать рабочий процесс калибровки и оценить практически достижимую точность.

В качестве эталонного используется абсолютный оптический энкодер ЛИР-ДА237Т (СКБ ИС) с разрешением 23 бита, что обеспечивает запас точности более чем на порядок.


## 2. Испытательный стенд

### 2.1. Общая схема

На общем валу установлены шаговый двигатель (400 полных шагов/оборот), магнит на заменяемом и регулируемом адаптере и оптический энкодер ЛИР-ДА237Т. Двигатель управляется драйвером TMC2225 (32 микрошага → 12800 микрошагов/оборот). Воздушный зазор между магнитом и чипом MT6835 — 1.8 мм.

Микроконтроллер STM32H503CB связан с MT6835 по SPI, с ЛИР-ДА237Т по BiSS-C (через аппаратный SPI) и с ПК по UART (115200 бод).

> Выбор STM32H503 ничем адекватно не обусловлен. Для подобных задач он избыточен и не рекомендуется — достаточно STM32F1xx. Основное требование к МК: минимум два аппаратных SPI и один UART/USB. Именно с выбором STM32H503 связано использование UART для связи с ПК, библиотеки USBx в новых сериях STM32 данному разработчику неподвластны.

### 2.2. ЛИР-ДА237Т

23-битный оптический абсолютный энкодер с интерфейсом BiSS-C. Дискретность: $360° / 2^{23} \approx 0.000043°$. Допустимая погрешность: ±30″ (±0.0083°) при номинальной температуре 20°C. Это на порядок точнее ожидаемой остаточной ошибки MT6835.

ЛИР-ДА237Т всегда выдаёт физический абсолютный угол — аппаратного обнуления в нём нет. Программное обнуление реализовано в прошивке STM32: при вызове `ENC_SetLIRZero()` текущий физический отсчёт запоминается как offset, и все последующие чтения вычитают его:

```c
void ENC_SetLIRZero(void) {
    ENC_ReadLIRRaw();
    lir_offset = lir_raw_physical;
    lir_raw_cached = 0;
    lir_degrees_cached = 0.0f;
}

uint32_t ENC_ReadLIRRaw(void) {
    // ... считывание BiSS-C фрейма, CRC-проверка ...
    uint32_t mask = (1ULL << num_bits) - 1;
    lir_raw_cached = (lir_raw_physical - lir_offset) & mask;
    return lir_raw_cached;
}
```

### 2.3. MT6835

*Табл. 1. Ключевые характеристики MT6835*

| Параметр                       | Значение                           |
| ------------------------------ | ---------------------------------- |
| Разрешение                     | 21 бит (2 097 152 отсчётов/оборот) |
| Интерфейс                      | SPI Mode 3, до 16.67 МГц           |
| INL после заводской калибровки | ±0.5° (тип.), ±1.0° (макс.)        |
| INL после User Auto-Cal        | ±0.07° (тип.)                      |
| INL после NLC                  | ±0.02° (заявлено)                  |

### 2.4. Связь STM32 и MT6835 по SPI

MT6835 использует SPI Mode 3 (CPOL=1, CPHA=1) с 24-битными транзакциями: 4 бита команды + 12 бит адреса + 8 бит данных. CSN — active low.

*Табл. 2. SPI-команды MT6835*

| Код | Команда        | Описание                             |
| --- | -------------- | ------------------------------------ |
| 0x3 | Read           | Чтение одного регистра               |
| 0x6 | Write          | Запись одного регистра               |
| 0xA | Burst Read     | Потоковое чтение ANGLE (0x003–0x006) |
| 0x5 | Auto Zero      | Установка текущей позиции как нуля   |
| 0xC | Program EEPROM | Запись всех регистров в EEPROM       |

Основная операция — чтение 21-битного угла через Burst Read. Чип возвращает 4 байта: ANGLE_H, ANGLE_M, ANGLE_L|STATUS, CRC. Каждое чтение защищено CRC8 по полиному $X^8 + X^2 + X + 1$:

```c
uint32_t ENC_ReadMT6835Raw(void) {
    uint8_t tx[6] = {0}, rx[6] = {0};
    tx[0] = (0xA << 4) | ((0x003 >> 8) & 0x0F);  // Burst Read @ 0x003
    tx[1] = 0x003 & 0xFF;

    HAL_GPIO_WritePin(CSN_Port, CSN_Pin, GPIO_PIN_RESET);
    HAL_SPI_TransmitReceive(&hspi1, tx, rx, 6, 10);
    HAL_GPIO_WritePin(CSN_Port, CSN_Pin, GPIO_PIN_SET);

    // rx[2]=ANGLE[20:13], rx[3]=ANGLE[12:5], rx[4]=ANGLE[4:0]|STATUS[2:0]
    uint32_t angle = ((uint32_t)rx[2] << 13)
                   | ((uint32_t)rx[3] << 5)
                   | ((uint32_t)(rx[4] >> 3));

    // CRC8 проверка: если не совпадает — используем предыдущее значение
    uint8_t crc_data[3] = {rx[2], rx[3], rx[4]};
    if (calculate_crc8(crc_data, 3) == rx[5])
        mt6835_raw_cached = angle;

    return mt6835_raw_cached;
}
```

Перевод в градусы:

$$\theta = \frac{angle}{2^{21}} \times 360°$$


## 3. MT6835: устройство и регистры

Внутренняя архитектура MT6835: два AMR-моста Уитстона формируют синусный и косинусный сигналы → АЦП → DSP-блок вычисляет угол (CORDIC) → применяются заводские калибровочные коэффициенты → NLC-коррекция → вычитание ZERO_POS → 21-битный выход.

Полная карта регистров приведена в даташите (раздел 8). Ниже описаны только те, которые непосредственно участвуют в калибровках.

### 3.1. ZERO_POS (0x009–0x00A)

12-битное значение (0–4095). Каждый отсчёт соответствует $360° / 4096 \approx 0.088°$. Угол, отдаваемый по SPI — это физический угол магнита *минус* значение ZERO_POS.

Чтение ZERO_POS из двух регистров:

```c
uint16_t ENC_GetMT6835ZeroPos(void) {
    uint8_t high = ENC_ReadMT6835Register(0x009);  // ZERO_POS[11:4]
    uint8_t low  = ENC_ReadMT6835Register(0x00A);  // ZERO_POS[3:0] в битах [7:4]
    return ((uint16_t)high << 4) | ((low >> 4) & 0x0F);
}
```

Установка ZERO_POS — SPI-команда Auto Zero (0x5). Чип записывает текущую позицию и подтверждает ACK=0x55:

```c
bool ENC_SetMT6835Zero(void) {
    uint8_t tx[3] = {0x50, 0x00, 0x00};
    uint8_t rx[3] = {0};
    HAL_GPIO_WritePin(CSN_Port, CSN_Pin, GPIO_PIN_RESET);
    HAL_SPI_TransmitReceive(&hspi1, tx, rx, 3, 10);
    HAL_GPIO_WritePin(CSN_Port, CSN_Pin, GPIO_PIN_SET);
    HAL_Delay(2);
    return (rx[2] == 0x55);
}
```

>NLC-таблица индексируется по физическому углу (до вычитания ZERO_POS). Изменение ZERO_POS *после* загрузки NLC сдвигает сетку коррекции относительно реальной ошибки, делая таблицу бесполезной, и даже вредной, т.к. коррекция будет применяться к неправильным углам.

### 3.2. HYST (0x00D, биты [2:0])

Окно гистерезиса выходного угла. Подавляет дрожание при малых колебаниях вала.

*Табл. 3. Значения HYST*

| Код [2:0] | Окно   | Примечание                  |
| --------- | ------ | --------------------------- |
| 0x0       | 0.022° |                             |
| 0x1       | 0.044° |                             |
| 0x2       | 0.088° |                             |
| 0x3       | 0.176° |                             |
| 0x4       | OFF    | Рекомендуется для измерений |
| 0x5       | 0.003° |                             |
| 0x6       | 0.006° |                             |
| 0x7       | 0.011° | Заводское значение          |

Для ступенчатых измерений в процессе оценки (вал неподвижен, пауза 400 мс), значение HYST никак не влияет на результат. Однако в динамических применениях и при высокой BW он может маскировать реальную ошибку.

### 3.3. BW (0x011, биты [2:0])

Полоса пропускания цифрового фильтра DSP. Компромисс между скоростью отклика и уровнем шума:

*Табл. 4. Значения BW*

| Код [2:0] | Полоса   | Примечание         |
| --------- | -------- | ------------------ |
| 0x0       | Baseline | Минимальный шум    |
| 0x1       | ×2       |                    |
| 0x2       | ×4       |                    |
| 0x3       | ×8       |                    |
| 0x4       | ×16      |                    |
| 0x5       | ×32      | Заводское значение |
| 0x6       | ×64      |                    |
| 0x7       | ×128     | Максимальная скорость отклика, максимальный шум |

При BW=Baseline кривая ошибки значительно чище — но для применений с быстрым вращением может не хватать скорости отклика.

### 3.4. NLC_EN (0x00C, бит 5) и NLC-таблица (0x013–0x0D2)

Бит NLC_EN включает применение 192-байтной NLC-таблицы. Запись NLC_EN — в RAM; чтобы сохранить между циклами питания, нужна команда Program EEPROM. Подробно о формате таблицы — раздел 6.

## 4. Read-Modify-Write: защита зарезервированных полей

При работе с регистрами MT6835 необходимо строго соблюдать паттерн read-modify-write. Ниже — подробности и примеры.

### 4.1. Проблема

Многие регистры MT6835 содержат рядом с пользовательскими битами поля «MagnTek Use Only» — заводские калибровочные коэффициенты (или что-то другое, достоверно определить невозможно). Документация не раскрывает их назначение, но они критичны для работы чипа. Например:

- Регистр 0x00C: бит [5] — NLC_EN (наш), биты [7:6] — MagnTek
- Регистр 0x00D: биты [2:0] — HYST (наш), биты [7:3] — частично MagnTek
- Регистр 0x00E: биты [6:4] — AUTOCAL_FREQ (наш), биты [3:0] — MagnTek (заводское = 0x8)
- Регистр 0x012: целиком MagnTek (заводское = 0xA0)

Если записать в регистр 0x00C значение `0x20` (только NLC_EN=1), а не `(текущее | 0x20)` — все биты MagnTek в этом регистре обнулятся. Это может быть незаметно, но после Program EEPROM испорченное значение станет постоянным. Какие изменения это может внести в работу энкодера — можно только предполагать.

### 4.2. Решение: read-modify-write

Каждая запись в регистр, содержащий зарезервированные биты, должна выполняться по схеме:

```c
// Правильно: read-modify-write
uint8_t reg = ENC_ReadMT6835Register(addr);   // 1. Прочитать текущее
reg = (reg & preserve_mask) | new_bits;         // 2. Изменить только нужные биты
ENC_WriteMT6835Register(addr, reg);             // 3. Записать обратно

// НЕПРАВИЛЬНО: прямая запись
ENC_WriteMT6835Register(addr, new_value);       // Уничтожает зарезервированные биты!
```

Конкретные примеры:

```c
// Установка HYST: биты [2:0] регистра 0x00D
static void HandleSetHystCmd(char *param) {
    uint8_t idx = atoi(param);
    uint8_t reg = ENC_ReadMT6835Register(0x00D);
    reg = (reg & 0xF8) | (idx & 0x07);  // маска 0xF8 сохраняет биты [7:3]
    ENC_WriteMT6835Register(0x00D, reg);
}

// Установка BW: биты [2:0] регистра 0x011
static void HandleSetBWCmd(char *param) {
    uint8_t idx = atoi(param);
    uint8_t reg = ENC_ReadMT6835Register(0x011);
    reg = (reg & 0xF8) | (idx & 0x07);
    ENC_WriteMT6835Register(0x011, reg);
}

// Включение NLC: бит [5] регистра 0x00C
bool ENC_SetNLCEnabled(bool enabled) {
    uint8_t reg = ENC_ReadMT6835Register(0x00C);
    if (enabled) reg |= 0x20;   // установить бит 5
    else         reg &= ~0x20;  // сбросить бит 5
    ENC_WriteMT6835Register(0x00C, reg);
    // Проверка:
    uint8_t readback = ENC_ReadMT6835Register(0x00C);
    return ((readback & 0x20) != 0) == enabled;
}

// Настройка AUTOCAL_FREQ: биты [6:4] регистра 0x00E
void ENC_ConfigureAutoCalRPM(int rpm) {
    uint8_t freq_val = /* ... вычисление из rpm ... */;
    uint8_t current = ENC_ReadMT6835Register(0x00E);
    uint8_t new_val = (current & 0x8F) | ((freq_val & 0x07) << 4);
    //                         ^^^^ сохраняем бит [7] и биты [3:0]
    ENC_WriteMT6835Register(0x00E, new_val);
}
```

### 4.3. Особая опасность: Program EEPROM

Команда Program EEPROM (SPI-код 0xC) записывает *все* регистры из RAM в энергонезависимую память. Это означает:

1. Если какой-либо зарезервированный бит испорчен в RAM — он навсегда попадёт в EEPROM
2. Восстановить заводские значения без специального оборудования MagnTek невозможно
3. Перед каждым Program EEPROM рекомендуется выполнить Read Registers и убедиться, что значения корректны

*Табл. 5. Критические заводские значения (проверять перед Program EEPROM)*

| Регистр | Заводское | Что хранит |
|---------|-----------|------------|
| 0x00E [3:0] | 0x8 | Калибровочные коэффициенты MagnTek |
| 0x012 | 0xA0 | Целиком MagnTek |

Если после Read Registers эти значения не совпадают с ожидаемыми — **не выполнять Program EEPROM** до выяснения причины.


## 5. Три уровня калибровки MT6835

### Уровень 1 — заводская калибровка

Компенсирует смещения (offset), рассогласование усиления (gain mismatch) и фазовую ошибку синусного/косинусного каналов AMR-мостов. Коэффициенты записаны в EEPROM на производстве. Типичная INL после заводской калибровки: ±0.5°, максимальная ±1.0° (на практике может быть много больше, ключевой фактор — воздушный зазор).

Ниже показана ошибка MT6835 с установленной заводской калибровкой, но *до* User Auto-Cal —  «из коробки». Характерная двухпериодная форма обусловлена структурой AMR.

При зазоре 3 мм (далеко от чипа, слабое поле):

![[3mm_distance_cleanIC_nocal.png|1000]]

### Уровень 2 — User Auto-Cal

Пользовательская авто-калибровка: магнит вращается с постоянной скоростью, на пине CAL_EN удерживается высокий уровень. По завершении коэффициенты автоматически записываются в EEPROM, после чего необходимо снять и подать питание микросхемы.

Регистр AUTOCAL_FREQ (0x00E, биты [6:4]) определяет ожидаемый диапазон скорости вращения. Прошивка автоматически выбирает значение по заданной скорости.

### Уровень 3 — NLC (Non-Linearity Compensation)

Пользовательская таблица из 256 точек коррекции, загружаемая в память MT6835. Единственный уровень, требующий внешнего эталона и понимания некоторых недокументированных параметров. Подробности — в собственном разделе далее.


## 6. NLC: формат, принцип работы

### 6.1. Общая структура

NLC-таблица MT6835 — это 256 корректирующих значений, каждое по 6 бит в формате дополнительного кода (two's complement): диапазон от -32 до +31. Таблица занимает 192 байта в регистрах 0x013–0x0D2 и представляет собой поправки к вычисленному углу на равномерной сетке с шагом $360° / 256 = 1.40625°$.

Когда NLC включена (бит NLC_EN=1), MT6835 для каждого измеренного физического угла находит ближайшие две точки сетки, интерполирует корректирующее значение и прибавляет его к углу.

### 6.2. NLC LSB — ключевой недокументированный параметр

Документация MagnTek не указывает, чему соответствует одна единица (LSB) корректирующего значения в градусах. Это ключевой параметр, без которого невозможно вычислить таблицу.

Экспериментально установлено и подтверждено на двух разных MT6835:

$$NLC\ LSB = \frac{360°}{2^{18}} = 0.001373°$$

Это ровно 8 отсчётов 21-битного угла ($2^{21} / 2^{18} = 8$). Подтверждение — серия тестов с загрузкой синтетических NLC-таблиц с известными амплитудами: измеренный эффект в градусах точно соответствует $A_{LSB} \times 0.001373°$ с погрешностью менее 1%.

### 6.3. Диапазон и насыщение

*Табл. 6. Диапазон NLC-коррекции*

| Параметр               | Значение    |
|------------------------|-------------|
| Одно значение          | -32..+31 LSB |
| LSB                    | 0.001373°   |
| Макс. коррекция точки  | ±0.044°     |
| Полный P2P диапазон    | ~0.087°     |
| Размер таблицы         | 256 × 6 бит = 192 байта |

Если de-meaned ошибка энкодера в конкретной точке превышает ±0.044° — корректирующее значение "упрется" в -32 или +31 (*saturation*), коррекция в этой точке будет неполной.

### 6.4. Упаковка MSB-first

Четыре 6-битных значения (A, B, C, D) упаковываются в 3 байта по схеме MSB-first:

```
Байт 0: [A₅ A₄ A₃ A₂ A₁ A₀ B₅ B₄]    → (A << 2) | (B >> 4)
Байт 1: [B₃ B₂ B₁ B₀ C₅ C₄ C₃ C₂]    → ((B & 0x0F) << 4) | (C >> 2)
Байт 2: [C₁ C₀ D₅ D₄ D₃ D₂ D₁ D₀]    → ((C & 0x03) << 6) | D
```

Реализация упаковки (Python):

```python
def _pack_msb(values):
    """Pack 256 signed 6-bit values into 192 bytes, MSB-first."""
    packed = bytearray()
    for i in range(0, 256, 4):
        v = [int(values[i + j]) & 0x3F for j in range(4)]
        packed.append(((v[0]) << 2) | ((v[1] >> 4) & 0x03))
        packed.append(((v[1] & 0x0F) << 4) | ((v[2] >> 2) & 0x0F))
        packed.append(((v[2] & 0x03) << 6) | (v[3]))
    return packed
```

Запись таблицы в MT6835 — побайтно, 192 регистра начиная с 0x013. После записи — включение NLC (бит 5 регистра 0x00C, обязательно через read-modify-write):

```c
bool ENC_WriteNLCTable(const char *hex_string) {
    for (int i = 0; i < 192; i++) {
        uint8_t byte = hex_to_byte(&hex_string[i * 2]);
        ENC_WriteMT6835Register(0x013 + i, byte);
    }
    // Включить NLC: бит 5 регистра 0x00C (read-modify-write!)
    uint8_t reg = ENC_ReadMT6835Register(0x00C);
    ENC_WriteMT6835Register(0x00C, reg | 0x20);
    return true;
}
```

### 6.5. Индексация по физическому углу

Точка "0" NLC-таблицы соответствует физическому углу 0° — а не пользовательскому нулю. При построении таблицы нужно учитывать ZERO_POS: ошибка измерена в пользовательских координатах, а таблица индексируется физическими. Сдвиг:

```python
# ZERO_POS в единицах NLC-сетки
shift = int(round(zero_pos_raw * 256 / 4096))
nlc_table = np.roll(nlc_from_user_angles, shift)
```

### 6.6. Автоматическое удаление постоянной составляющей

MT6835 вычитает среднее значение из NLC-таблицы перед применением. Результат: таблица, заполненная одинаковыми значениями (например, все 16), эквивалентна таблице с нулями во всех ячейках — эффекта не будет. На коррекцию влияет только *разница* между значениями в разных точках.

### 6.7. Знак коррекции

Положительное значение в NLC-таблице *прибавляет* угол к выходу. Для компенсации положительной ошибки нужно отрицательное корректирующее значение:

$$correction_i = -\frac{error_i}{NLC\ LSB}$$

```python
correction_lsb = -error_demeaned / NLC_LSB_DEGREES
nlc_values = np.clip(np.round(correction_lsb).astype(int), -32, 31)
```

## 8. Математика оценки линейности

### 8.1. Определение ошибки

Ошибка определяется как разность между показанием MT6835 и эталонным значением ЛИР-ДА237Т:

$$error(\theta) = \theta_{MT6835} - \theta_{LIR}$$

Поскольку оба энкодера обнуляются в одной точке (Home), разность непосредственно отражает нелинейность MT6835. Вклад ЛИР (±0.0083°) пренебрежимо мал по сравнению с ошибкой MT6835 (>0.05°).

Необходима коррекция перехода через 0°/360°. Без неё, если MT6835 показывает 359.9°, а ЛИР-ДА237Т — 0.1°, разность будет 359.8° вместо правильных -0.2°. Решение: если абсолютная разность больше половины оборота — значит, один из энкодеров «перешёл через ноль», и нужно скорректировать на 360°:

```python
error = mt_deg - lir_deg
# Если error > 180°, значит MT "убежал вперёд" через 360° → вычитаем оборот
error[error > 180] -= 360
# Если error < -180°, значит LIR "убежал вперёд" → прибавляем оборот
error[error < -180] += 360
# Теперь error всегда в диапазоне [-180°, +180°]
```

### 8.2. Метрики

*Табл. 8. Метрики оценки линейности*

| Метрика            | Формула                | Назначение                          |
|--------------------|------------------------|-------------------------------------|
| P2P                | $\max - \min$          | Полный размах ошибки                |
| RMS                | $\sqrt{mean(error^2)}$ | Среднеквадратичная ошибка           |
| Mean               | $mean(error)$          | Постоянное смещение (не нелинейность) |
| **De-meaned P2P**  | $P2P(error - Mean)$    | **Основная метрика для NLC**        |

Все графики в этой работе показывают de-meaned ошибку: постоянное смещение вычтено, остаётся только нелинейность.

### 8.3. Ступенчатый сбор данных

Алгоритм сбора реализован конечным автоматом в `calibration.py`. Первая точка снимается на позиции Home (~0°), затем шаг → пауза → снятие, и так далее:

```
SAMPLE(Home) → MOVE → SETTLE (400 мс) → SAMPLE → MOVE → SETTLE → SAMPLE → ...
```

На каждой позиции: пауза 400 мс для стабилизации, затем 12 отсчётов с интервалом 50 мс. Медиана 12 значений — результат для данной точки. Поскольку первая точка снимается на позиции Home (≈0°), измерения непосредственно ложатся на NLC-сетку без интерполяции.

*Табл. 9. Параметры ступенчатого сбора данных*

| Параметр                    | Значение        |
| --------------------------- | --------------- |
| Микрошагов/оборот           | 12800           |
| Шаг между точками (256 pts) | 50 µst = 1.406° |
| Settle time                 | 400 мс          |
| Отсчётов на точку           | 12 (медиана)    |
| Интервал отсчётов           | 50 мс           |

### 8.4. Прямое присвоение ошибки на NLC-сетку

NLC-таблица MT6835 содержит 256 точек на равномерной сетке с шагом 1.406° (0°, 1.406°, 2.813°, ..., 358.594°). Поскольку первая точка снимается на позиции Home (≈0°), а шаг двигателя (50 микрошагов = 1.406°) совпадает с шагом NLC-сетки, измеренные значения ошибки напрямую соответствуют точкам NLC-таблицы:

- Точка 0 (Home, ≈0°) → NLC0
- Точка 1 (≈1.4°) → NLC1
- ...
- Точка 255 (≈358.6°) → NLC255

Вычисление NLC-таблицы из собранных данных:

```python
error = mt_deg - lir_deg
error[error > 180] -= 360
error[error < -180] += 360
error_ac = error - np.mean(error)         # DC removal (чип сделает это сам)
correction = np.clip(np.round(-error_ac / NLC_LSB).astype(int), -32, 31)
```


## 9. Рабочий процесс калибровки NLC

### 9.1. Полный процесс «с нуля»

1. **Подготовка стенда.** Магнит соосно с MT6835, зазор 1.5–1.8 мм.
2. **User Auto-Cal.** Выбрать скорость (50–100 RPM лучше всего), нажать «Auto-Cal». Дождаться SUCCESS в консоли. Снять питание. Подать питание.
3. **Home** — переместиться к нулю ЛИР-ДА237Т.
4. **Set Zero Pos** — установить ZERO_POS MT6835. Это **обязательный ручной шаг**, программа не выполняет его автоматически.
5. **Collect Data** (256 points) — это baseline без NLC.
6. **Generate NLC** — программа вычислит таблицу, покажет прогноз, сохранит `.hex`.
7. **Upload NLC** — выбрать сгенерированный файл, загрузить в чип → запись RAM + EEPROM.
8. **Collect Data** повторно — оценить эффект коррекции.
9. При необходимости повторить: Clear NLC → Home → новый baseline → Generate → Upload.

### 9.2. Возможные проблемы

**Насыщение NLC.** Типичная ситуация: ошибка после User Auto-Cal ~0.15° P2P (de-meaned), а весь диапазон NLC — лишь ±0.044°. Значительная часть точек будет ограничена до ±32, и в этих зонах коррекция неполная:

**Неправильный NLC LSB.** Если при вычислении таблицы использовать неверный LSB, коррекция будет «недотягивать» или «перетягивать». Сравнение LSB=8ct (правильный) и LSB=16ct (вдвое завышенный):

## 10. Факторы, влияющие на точность

### 10.1. Соосность (DISP — off-axis displacement)

Смещение оси магнита относительно центра чувствительного элемента MT6835 — главный механический фактор. По данным даташита MagnTek, при Ø6 мм магните и зазоре 1.5 мм: смещение 0.3 мм увеличивает INL с ~0.2° до ~0.5°. Для максимальной точности рекомендуется DISP < 0.05 мм, что потребует прецизионной механической обработки деталей и/или ручной юстировки.

### 10.2. Воздушный зазор

Увеличение зазора ослабляет магнитное поле и повышает чувствительность к соосности. Эффект значительно выражен — необходим экспериментальный подбор зазора. Рекомендуемые значения: 0.5–1.5мм.

### 10.3. Жёсткость крепления

Для NLC-калибровки с дискретностью ~0.001° механическая повторяемость должна быть на уровне единиц угловых секунд. Любой люфт, прогиб, вибрация в цепи «магнит — вал — чип» непосредственно вносят угловую ошибку. Упругие муфты, пружинные элементы — в идеале недопустимы.

### 10.4. Температура

AMR-элементы и магниты имеют свои температурные коэффициенты. NLC-таблица фиксирована и не адаптируется к температуре. Калибровка, выполненная при 25°C, будет неоптимальна при -20°C или +80°C.

### 10.5. Внешние магнитные поля

Близко расположенные моторы, трансформаторы, силовые провода могут искажать карту магнитного поля. MT6835 измеряет *направление* поля (AMR), а не амплитуду — но достаточно сильное внешнее поле наложится на поле магнита и внесёт систематическую ошибку.

### 10.6. Привязка калибровки к месту установки

**Критически важно для практического применения.** NLC-калибровка действительна только для конкретной механической конфигурации: данный зазор, данная соосность, данный магнит, данное крепление. Если энкодер перемонтирован, или изменился зазор, или заменён магнит — калибровка недействительна и требует повторения.

Для серийного применения это означает одно из двух:
- Проектировать механику так, чтобы User Auto-Cal (±0.07°) было достаточно. Вполне рабочий вариант.
- Предусмотреть процедуру NLC-калибровки по месту: внешний калибровочный стенд (ЛИР-ДА237Т + мотор + управляющий контроллер) в виде "модуля" к конечному изделию для произведения калибровки на месте.

### 11.3. Формат телеметрии STATUS

```
STATUS_LIR-DA237T_POS:<raw>,
STATUS_MT6835_POS:<raw>,
STATUS_MT6835_RAW:<physical>,
STATUS_MT6835_ZERO_POS:<12bit>,
STATUS_MT6835_HYST:<0-7>,
```

Поле `MT6835_RAW` содержит физический угол (до вычитания ZERO_POS), восстановленный в прошивке:

```c
uint32_t zero_21bit = (uint32_t)zero_pos * 512u;  // масштаб: 2^21 / 2^12
uint32_t mt_physical = (mt_raw + zero_21bit) & 0x1FFFFF;
```


## 12. Заключение

Создан испытательный стенд и управляющее ПО для оценки точности и линейности, а также калибровки магнитного энкодера MT6835. Экспериментально определены все недокументированные параметры NLC-коррекции: NLC LSB = $360° / 2^{18} = 0.001373°$, упаковка MSB-first, индексация по физическому углу. Подтверждена достижимая точность и линейность, при точной настройке механики — значительно лучше заявленной в даташите. 

**Главное практическое ограничение:** NLC-калибровка привязана к конкретной механической сборке. Любое изменение зазора, соосности или магнита требует повторной калибровки с внешним эталоном.
